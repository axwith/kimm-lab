# 국가 R&D 과제 파이프라인 — 공고 탐색부터 발표까지

> 공고를 찾아 → 적합한 걸 고르고 → 근거를 모아 → 아이디어를 만들고 → **연구개발계획서를 나눠 쓰고** → 발표까지 가는 전 과정의 정본.
> 각 단계는 커맨드가 담당하고, 단계 사이에는 **게이트**가 있다. 게이트를 통과하지 않고 다음으로 넘어가지 않는다.

---

## 전체 흐름

```
P0 탐색      /grant search {키워드}          → 공고 후보 목록
   ├─ 게이트 ①: 후보 3~5건으로 좁혔는가
P1 선정      /grant fit {공고}               → 적합도 판정 (적합/조건부/부적합)
   ├─ 게이트 ②: '적합' 또는 '조건부'가 1건 확정됐는가  ← 부적합이면 P0로 되돌아간다
P2 리서치    insane-research 스킬 + /lit    → 시장기회·트렌드·핵심기술 요구사항
   ├─ 게이트 ③: 유형①(외부 사실) 주장이 출처 기준을 통과했는가
P3 아이디어  /grant ideate {공고}            → 과제 아이템 (요건에서 역산)
   ├─ 게이트 ④: 모든 아이템이 요건 행에 연결됐는가
P4 서사      /proposal story               → 스토리라인 (왜 지금·왜 우리·왜 이 방법)
   ├─ 게이트 ⑤: 한 문장 요약이 나오는가
P5 계획서    /proposal A → B → C           → 연구개발계획서 (3페이즈 분할)
   ├─ 게이트 ⑥: 페이즈마다 사람 확인
P6 발표설계  (이 공간 범위 밖, 별도 발표 도구) → 스토리보드
P7 슬라이드  (이 공간 범위 밖)              → 덱
```

## P0 — 공고 탐색

```bash
python3 60-scripts/rnd_ancm.py ntis --limit 50                    # 넓게: 전 부처 접수중
python3 60-scripts/rnd_ancm.py iris --keyword "{키워드}" --limit 30 # 깊게: 40필드 구조화
```

**발견은 NTIS, 분석은 IRIS.** IRIS만 서버 키워드 검색이 된다.

| | NTIS | IRIS |
|---|---|---|
| 성격 | 국가R&D **통합공고** 포털 | 범부처통합연구지원시스템 |
| 규모 | 누적 공고 일련번호 **77,012**(1995~) · **접수중은 30~40건 수준**(2026-08-03 실측 33건) | 누적 **12,482**건 |
| 필드 | 7컬럼(순번·현황·공고명·부처·접수일·마감일·D-day) | **40필드**(전문기관·사업명·공모분야·제출서류유형 등) |
| 키워드 검색 | ❌ 서버 파라미터 미확정 → 로컬 필터 | ✅ `bsnsAncmTl`/`ancmTl` |

> ⚠️ **77,012는 누적 일련번호지 지금 지원 가능한 공고 수가 아니다.** 실제 접수중은 수십 건이다.
> ⚠️ 부처별 개별 공고 사이트는 두 포털에 다 안 잡힐 수 있다 — **커버리지 한계**로 기록한다.

`50-grants/_raw/_candidates-{날짜}.md`에 후보를 모은다. 이 단계에서 **버리지 않는다** — 거르기는 P1이다.

### P0.5 — 공고 유형 분류 ★ (2026-08-03 신설)

> **NTIS「국가R&D통합공고」에는 서로 다른 종류가 섞여 있다.** 이름만 보고 전부 R&D 과제로 다루면
> 산출물 자체가 틀린다. 실측(2026-08-03): 무인수상정 건은 국방과학연구소 **용역 입찰**이었다.

| 유형 | 식별 신호 | 산출물 | 자격 축 |
|------|----------|--------|--------|
| **A. 조달 입찰(용역)** | "입찰공고문"·"제안요청서"·"낙찰자 결정방법"·"예비가격기초금액"·전자조달 | **제안서** (제안요청서 평가항목 순서) | 업종코드·직접생산확인증명서·기업규모 |
| **B. R&D 과제** | "신규지원 대상과제 공고"·"신청용 연구개발계획서"·전문기관(평가원/재단) | **연구개발계획서** (양식 8장) | 기관유형·참여의사확인서·적정성확인서 |
| **C. 기술수요조사** | "기술수요조사"·"기획을 위한" | **수요서/의견서** (짧음) | 대체로 느슨 |
| **D. 사전공고** | "사전공고" — 붙임이 없거나 적음 | (본공고 대기) | 미확정 |

**판별 방법**: 붙임 파일명을 본다. `제안요청서`가 있으면 A, `신청용 연구개발계획서`가 있으면 B다.

```bash
python3 60-scripts/rnd_ancm.py detail --uid {roRndUid}          # 붙임 목록만
python3 60-scripts/rnd_ancm.py detail --uid {uid} --download-dir 50-grants/_raw/{건}
```

> **게이트 ⓪** — 유형이 판별됐는가. **D(사전공고)면 진행하지 않는다**(요건이 아직 없다).
> 유형에 따라 P5 산출물과 §1.5 자격 축이 갈린다.

> **게이트 ①** — 후보를 3~5건으로 좁혔는가. 10건 이상이면 키워드가 넓은 것이고, 0건이면 좁은 것이다.

## P1 — 적합도 판정과 선정

`/grant fit {공고}` → `frameworks/rfp-fit-matrix.md` 호출.

- 공고문·붙임을 **전부** 확보한다(P0.5 스크립트). HWP 변환은 `npx -y kordoc {파일}.hwp --format markdown`.
- 요건을 **원문 표현 그대로** 표로 분해한다.
- ★ **요건표에 '과업' 구분을 반드시 포함한다** (2026-08-03 추가). RFP의 **연구내용·추진방법**을 요건으로 등록하지 않으면
  P3 아이디어 역산의 **연결 대상이 없어 게이트 ④가 성립하지 않는다.**
- ★ **입력 잠금 체크리스트** — 아래를 확보했는지 확인한다. 없으면 해당 게이트는 '판정 불가'로 남는다.
  자격 요건 · 계획서 양식(목차·분량·서식) · **평가 배점표**(붙임과 공고문 본문 양쪽) · **「국가연구개발사업 연구개발비 사용 기준」**(예산 게이트 ②의 입력)
- **평가 배점표가 진짜 요구사항이다.** 붙임에 숨어 있으면 그게 최우선 문서다.

> **게이트 ②** — '적합' 또는 '조건부'가 **1건** 확정됐는가.
> 부적합이면 **P0로 되돌아간다.** 요건을 느슨하게 해석해서 통과시키지 않는다.
> 조건부면 **파트너·비용·철수 시점**이 적혀 있어야 통과.

## P2 — 리서치 (시장기회·트렌드·핵심기술 요구사항)

**여기서 `/insane-research`를 쓴다.** 축을 갈라 병렬로 돌리고, 문헌 축만 `/lit`으로 따로 처리한다.

| 축 | 무엇을 캐는가 | 도구 |
|----|-------------|------|
| **시장기회** | 시장 규모·성장률·수요처·조달 구조. 공공 R&D면 **정책 수요**가 시장이다 | `/insane-research` |
| **트렌드** | 최근 3년 기술·정책 변화 방향. **어디로 가고 있는가** | `/insane-research` |
| **핵심기술 요구사항** | 공고가 요구하는 성능·기능을 기술 수준으로 번역. 현 SOTA와의 격차 | `/lit` + `/insane-research` |
| **경쟁·선행** | 같은 문제를 누가 어떻게 풀었나. **선행연구와 경쟁 과제** | `/lit` |
| **규제·표준** | 인증·표준·법령 제약 (5-2 표준화 전략의 재료) | `/insane-research` |

산출은 `50-grants/{공고명}/`에. 소스는 `10-literature/sources/`에 A~E 등급으로 등재.

> **게이트 ③** — 리서치 산출 주장이 **유형①(외부 사실)** 기준을 통과했는가.
> 계획서 본문은 5유형 체계를 쓴다(`frameworks/output-correctness.md` §2) — ①외부사실 ②전망 ③내부가정 ④연구가설 ⑤목표.
> **유형①로 쓸 수치는 여기서 확정된 것만.** 나머지 유형은 P5에서 각자의 표기 의무를 진다.

### 게이트 ③-b — **'미확인'과 '미조사'를 가른다** ★ (2026-08-03 신설)

"확인하지 못했다"고 적은 항목을 **전부 다음 셋 중 하나로 강제 분류**한다. 분류 없이 `미확인`으로 남기는 것을 금지한다.

| 분류 | 뜻 | 처리 |
|------|-----|------|
| **A. 조사 가능** | 공개 소스·전화 한 통이면 확인된다 | **지금 조사한다.** 계획서에 "미확인"으로 남길 수 없다 |
| **B. 착수 후 확정** | 협약·선정 이후에만 정해진다 | 유형③(내부가정)으로 명시하고 확인 시점을 적는다 |
| **C. 연구 과업** | 이 과제가 밝혀낼 대상이다 | 유형④(연구가설)로 전환한다 — **결함이 아니라 연구 목적이다** |

**A 판정 기준 — 아래에 해당하면 무조건 A다.**
- 법령·조문 → 국가법령정보센터 · 국회 의안정보시스템
- 사업 규정·비목 한도 → 소관부처 고시·훈령 (대개 공개)
- 공고 조건(부담금·보안등급·제출서류) → 공고문 본문 또는 **전문기관 전화**
- 연구자 참여율 → IRIS 연구자 정보
- 통계 원자료 접근성 → 제공기관 이용 안내

**작성 규율**: 제출본에 *"확인하지 못했다"*, *"확인 불가"* 문장을 **쓰지 않는다.** B는 가정으로, C는 가설로 표현한다.

> **실측 근거**: 2026-08-03 데모에서 '미확인 8건' 중 **6건이 A(조사 누락)**였다.
> 그중 법령 조문 미확인은 계획서의 **중심 문제 정의를 틀리게** 만들었다.
> research-lab 저장소의 2026-08-03 데모 검토 기록 D1·D6

### 게이트 ③-c — 리서치 에이전트 산출 확인 ★ (2026-08-03 신설)

병렬 서브에이전트로 리서치를 돌렸다면, **다음 단계로 넘어가기 전에 산출 파일의 존재와 내용을 실제로 확인한다.**

- [ ] 띄운 에이전트 수 = 산출 파일 수
- [ ] 각 파일이 **빈 파일·헤더만 있는 파일이 아니다**
- [ ] 실패한 축은 **메인 스레드에서 직접 조사**하거나, 못 했으면 **결함으로 등재**한다

> **실측 근거**: 2026-08-03 데모에서 리서치 서브에이전트 **4/4가 응답 없이 유휴 종료**했고,
> 이를 알아채지 못한 채 진행해 도메인 고유명사·해외 사례가 전부 자리표시자로 남았다.
> 리서치 레이어의 조용한 실패는 **아래 모든 단계의 품질 상한을 결정한다.**

## P3 — 과제 아이디어 도출

`/grant ideate {공고}` — **하고 싶은 걸 공고에 끼워 맞추지 않는다. 공고가 요구하는 결과에서 역산한다.**

아이템마다: 산출물(명사) / 충족 요건 행번호 / 정량지표 달성·측정 방법 / 수행 주체 / 실패 위험.

> **게이트 ④** — 모든 아이템이 **요건 행에 연결**됐는가. 연결 안 되는 아이템은 뺀다.

## P4 — 스토리텔링 설계

`/proposal story` — 계획서 전체를 관통할 **한 줄**과 3단 논리를 만든다.

| 축 | 질문 | 어디서 재료가 오나 |
|----|------|-----------------|
| **왜 지금인가** | 왜 지금 해야 하고, 안 하면 무엇을 잃는가 | P2 트렌드·정책 |
| **왜 우리인가** | 왜 우리가 해야 유리한가 | P1 적합도 매트릭스 '보유' 항목 |
| **왜 이 방법인가** | 왜 이 접근이 대안보다 나은가 | P2 선행·경쟁, P3 아이템 |

> **게이트 ⑤** — **한 문장 요약**이 나오는가. 안 나오면 아직 과제가 정리되지 않은 것이다.
> *"○○ 문제를 △△ 방법으로 풀어 □□를 달성한다"* 형태로.

## P5 — 연구개발계획서 (3페이즈 분할) ★

**한 번에 쓰지 않는다.** 5개 장은 의존 관계가 있어서, 앞이 확정되지 않으면 뒤가 흔들린다.

### Phase A — 근거층 (1장 + 2-1)

| 절 | 내용 | 재료 |
|----|------|------|
| 1-1 | 연구개발과제의 개요 | P4 한 문장 + P3 아이템 |
| 1-2 | 연구개발 대상의 국내외 현황 | **P2 리서치 (verified만)** |
| 1-3 | 사회문제 해결 방안 개요 *(해당 시)* | P2 정책·수요 |
| 2-1 | 최종 목표 | P1 요건 정량지표 + P3 |

> **A 게이트**: 1-2의 모든 수치에 출처·등급이 붙었는가. 최종목표가 공고 정량지표와 **숫자까지 일치**하는가.

### Phase B — 실행층 (2-2~2-4 + 3장)

| 절 | 내용 | 재료 |
|----|------|------|
| 2-2 | 단계별 목표 *(해당 시)* | 2-1을 연차로 분해 |
| 2-3 | 연구 내용 | P3 아이템 → 세부 과업 |
| 2-4 | 수행일정 및 주요 결과물 | 2-3 × 기간, 산출물 명시 |
| **B-2** | **사업비 계획** ★ | 공고 사업비 산정 기준표 + 2-3 과업 역산 |
| **B-3** | **정량 목표 보강** ★ | 기준선·목표치·측정법 3종 세트 |
| 3-1 | 추진 전략·방법 | P4 "왜 이 방법인가" |
| 3-2 | 추진 체계 | P1 매트릭스의 '조달 가능' 항목 = 컨소시엄 |

> **B 게이트**: 2-3의 모든 과업이 2-1 목표에 연결되는가. 2-4에 **측정 가능한 결과물**이 있는가. 3-2에 **역량 공백을 메울 주체**가 명시됐는가.
> **예산**: 총액이 공고 한도 이내인가 · 항목 비율이 기준표 이내인가 · **모든 과업에 예산이 붙었는가**.
> **KPI**: 정량 지표마다 기준선·목표치·측정법이 다 있는가.

### Phase C — 성과층 (4장 + 5장)

| 절 | 내용 | 재료 |
|----|------|------|
| 4-1 | 연구개발성과의 활용방안 | 2-4 결과물 → 수요처 |
| 4-2 | 기대효과 | **P2 시장기회 (verified 수치만)** |
| 5-1 | 사업화 계획 | P2 시장·조달 구조 |
| 5-2 | 표준화 전략 | P2 규제·표준 |
| 5-3 | 공개SW 활용화 전략 *(해당 시)* | 라이선스 방침 |

> **C 게이트**: 4-2 기대효과의 정량 수치가 **P2에서 verified된 것**인가(추정치 금지). 5-1이 4-1과 모순되지 않는가.

**페이즈 사이마다 사람이 확인한다**(게이트 ⑥). 확인 없이 다음 페이즈로 넘어가면, 앞이 바뀔 때 뒤를 전부 다시 써야 한다.

## P6~P7 — 발표 설계와 슬라이드

발표 덱은 이 공간 범위 밖입니다. 스토리보드까지만 `50-grants/{공고명}/deck-outline.md`에 남깁니다.

- 발표는 계획서 요약이 아니다. **평가위원이 판단해야 할 것만** 남긴다.
- 목차 순서가 아니라 **배점 순서**로 짠다.

## KB 층 — 파이프라인을 가속하는 축적

`00-inbox/`에 자료를 던져두고 Claude에게 `70-kb/`로 정리해 달라고 하면 출처와 함께 쌓인다.
**두 번째 과제부터 파이프라인이 훨씬 빨라진다.**

| KB 폴더 | 어느 게이트를 앞당기나 |
|---------|---------------------|
| `agencies/` | P1 배점 역설계 — 이 기관이 뭘 중시하는지 이미 안다 |
| `programs/` | P0 탐색 — 이 사업의 연차 패턴·예산 규모를 안다 |
| `requirements/` | P1 요건 분해 — 반복 출현 요건은 표를 재사용한다 |
| `our-assets/` | **P1 '보유' 판정** — 증빙까지 정리돼 있어 매트릭스가 즉시 채워진다 |
| `outcomes/` | **P5 체크리스트** — 과거 탈락 사유가 그대로 검토 항목이 된다 |
| `domain/` | P2 리서치 — 이미 조사한 건 다시 안 한다 |

> 파이프라인 각 단계는 **KB를 먼저 조회하고**, 없을 때만 새로 조사한다.
> `outcomes/`의 심사 의견이 가장 값지다 — 왜 됐고 왜 떨어졌는지가 다음 계획서의 게이트가 된다.
