# KB 구축 가이드 — 강의 뒤에 내 지식베이스를 키우는 법

오늘은 최근 자료 10개 이내로 KB를 시작했습니다. 이 워크스페이스는 공고 적합도(`/grant fit`), 시나리오(`/scenario`), 기획서(`/paper` `/plan`)를 쓸 때 모두 `70-kb` 를 먼저 읽습니다. KB가 쌓일수록 결과가 내 실적과 문체에 맞아집니다.

## 1. 넣기 전에 — 보안부터

- 소속 기관의 AI 사용 지침을 먼저 확인합니다. Claude Code가 읽은 파일은 처리를 위해 Anthropic 서버로 전송됩니다.
- 이미 공개한 자료(논문, 학회 발표, 공개 보고서)부터 넣습니다.
- 미공개 자료는 기관이 승인한 환경에서만 다룹니다. 프로필에는 `[비공개]` 로만 적습니다.
- KB에는 요약과 원본 위치만 남습니다. 원본은 `00-inbox/_done/` 에 있습니다.

## 2. 넣는 순서 — 묶음으로 나눠서

1. 한 번에 10~20개씩 `00-inbox/` 에 넣고 `/kb ingest` 를 돌립니다. 결과 표를 확인한 뒤 다음 묶음을 넣습니다. 수백 개를 한꺼번에 넣지 않습니다.
2. 최근 것과 대표작부터 넣고, 오래된 것은 나중에 넣습니다.
3. HWP는 PDF로 저장해서 넣습니다.

| 우선순위 | 자료 | KB에서 쓰이는 곳 |
|---|---|---|
| 1 | 평가 결과·심사 의견 | 왜 됐고 왜 떨어졌는지(`outcomes`). 가장 값진 자료 |
| 2 | 과거 계획서·결과보고서 | 실적 증빙(`assets`), 문서 구성(`style`) |
| 3 | 논문·특허 | 실적 증빙, 방법·용어 |
| 4 | 장비·데이터 목록 | 보유 역량. 증빙이 있어야 "보유" |
| 5 | 발표 자료 | 문장·구성 습관(`style`) |

## 3. 넣은 뒤에 — 확인

- `/kb 내 실적 중 ○○ 관련만 보여 줘` 처럼 물어보고, 답에 원본 위치가 붙는지 봅니다.
- `70-kb/style/작업스타일.md` 가 내 문체와 다르면 직접 고치거나 "이 부분 틀렸어"라고 말해 고칩니다.
- `/kb gaps` 로 비어 있는 칸을 보고 다음 묶음에 넣을 자료를 정합니다.

## 4. 유지 — 쌓이게 두는 습관

- 논문이 나오거나 과제가 끝날 때마다 바로 `00-inbox/` 에 넣고 `/kb ingest`.
- 한 달에 한 번 `/kb check`: 중복, 낡은 정보, 증빙 없는 "보유"를 정리합니다.
- 공고 판정 결과는 `/grant fit` 이 `outcomes` 에 남깁니다. 같은 사업을 두 번 조사하지 않습니다.

## 5. 자동으로 돌리기 — 기록과 공고

| 무엇 | 언제 | 어떻게 |
|---|---|---|
| 세션 기록 원자료 | 세션이 끝날 때마다 | 훅(`session_end_queue.py`)이 `90-log/_queue/` 에 자동으로 남김. 할 일 없음 |
| 기록 정리 | 다음 세션 시작 때 | CLAUDE.md 규칙이 대기열을 먼저 정리하고 최근 기록을 요약 |
| 하루 마감 `/wrap` | 매일 18:00 | 예약 실행 |
| 주간 공고 `/weekly` | 매주 월 08:30 | 예약 실행. 결과는 `50-grants/{날짜}-weekly.md` |

예약 실행 등록(한 번만, Claude Code CLI 설치·로그인 필요):
- Windows: `powershell -ExecutionPolicy Bypass -File 60-scripts\schedule_windows.ps1`
- macOS: `bash 60-scripts/schedule_mac.sh`

예약 실행은 승인 창에 답할 사람이 없으므로 파일 편집, 대기열 파일 옮기기, python 스크립트, 웹 조회만 허용해 둡니다. 결과는 다음 날 열어 확인합니다(`logs/schedule-wrap.log`, `logs/schedule-weekly.log`). Windows에서 등록을 풀려면 PowerShell에서 `Unregister-ScheduledTask -TaskName research-planner-wrap -Confirm:$false` (weekly도 같은 방식).
