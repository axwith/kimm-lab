# /lab3 — 실습 3 · 주제 하나로 끝까지

공통 규칙: `.claude/skills/_공통규칙.md` (흐름·막힐 때·정리 방식)

## 전체 보기 (맨 먼저 그대로 출력)

```
실습 3 — 주제 하나로 찾기부터 기획서까지

목표: 주제 하나를 정해 논문 → 공고 → 주제 고르기 → 기획서까지 한 흐름으로 이어 갑니다.
앞 단계가 남긴 파일을 다음 단계가 읽습니다.

STEP 1. 질문하기 — /lit 으로 문헌표와 "빈틈"을 받습니다
STEP 2. 검토하기 — /grant search 로 공고를 찾고, /grant fit 으로 나랑 맞는지 봅니다
STEP 3. 기획하기 — /scenario 로 후보 주제를 비교하고 하나는 내가 고릅니다
STEP 4. 만들기 — /plan 으로 기획서 초안을 씁니다
STEP 5. 개선하기 — 형식 검사에서 빠진 절을 채웁니다

끝나면 남는 것: 10-literature/ 문헌표, 50-grants/ 공고 목록과 적합도 판정,
20-scenarios/ 비교표, 40-plans/ 기획서 초안
```

## 선택 (AskUserQuestion)

먼저 `70-kb/profile/연구프로필.md` 의 관심 주제를 읽습니다(읽기만).
- header `주제`, question "어떤 주제로 할까요?"
  - "프로필의 관심 주제: {관심 주제}" — 프로필이 있을 때만 넣습니다
  - "강사 주제: AI 에이전트로 연구자의 문서 업무 줄이기" — 강사 화면과 같은 결과로 따라 갑니다. 프로필 관심 주제와 같은 문구면 이 선택지는 빼고 하나만 둡니다
  - (그 밖에는 Other 로 직접 입력)
- 프로필이 없으면 선택지 밖에 "/lab2 를 먼저 하면 내 관심 주제가 자동으로 들어갑니다"라고 한 줄 붙입니다.

## 자동 셋업

- 고른 주제를 `.lab-progress.json` 의 `lab3.topic` 에 적습니다. 이후 `/lit` `/grant search` `/scenario` 를 주제 없이 부르면 이 주제를 씁니다.
- `70-kb/assets/보유역량.md` 에 행이 있는지 봅니다. 없으면 "STEP 2의 적합도 판정이 비어 나옵니다. /lab2 를 먼저 하면 정확해집니다"라고 알립니다.
- 한 줄 보고: "실습 3 준비 완료. 주제: {주제}. KB 보유 {N}·부분 {N}. 강사 결과 예시: examples\모범결과\lab3\"

## 브리핑 + 진행 안내 (고른 주제를 넣어 출력)

````
■ 이번 실습에서 쓰는 것
| 명령 | 한 줄 정의 | 남는 곳 |
|---|---|---|
| /lit | 논문을 찾아 문헌표와 빈틈을 정리, 끝에 인용 검사 | 10-literature |
| /grant search | NTIS·IRIS 국가 R&D 공고를 스크립트로 검색 | 50-grants |
| /grant fit | 공고 요건을 내 KB와 대조해 보유·부분·없음 판정 | 50-grants |
| /scenario | 앞 파일들을 읽고 후보 주제를 여섯 기준으로 비교 | 20-scenarios |
| /plan | 고른 시나리오로 기획서 초안, 끝에 형식 검사 | 40-plans |

흐름: 문헌 → 공고 → (시장) → 주제 고르기 → 기획서 → 검사
핵심: 사실 확인은 스크립트와 검토 담당이, 고르는 일은 내가 합니다.

■ STEP 1. 질문하기 — 문헌 찾기
```
/lit {주제}
```
- 범위를 물으면 기본값(최근 5년, 영어+한국어)으로 답합니다
- 10-literature 의 문헌표를 열고 맨 아래 "빈틈" 절을 꼭 읽습니다
- 인용 확인을 따로 맡기려면:
```
citation-reviewer 에게 이 문헌표의 핵심 주장마다 근거가 충분한지 검토시켜 줘
```
확인할 것: 끝의 인용 검사 결과 줄과 "미확인" 절이 남아 있습니다

■ STEP 2. 검토하기 — 공고 찾고 나랑 맞는지 보기
```
/grant search {짧은 검색어, 예: 인공지능}
```
- 0건이면 검색어를 넓혀 다시 찾는지 봅니다. 50-grants 의 목록에서 접수 기간과 관련성을 읽습니다
- 목록에서 하나를 골라:
```
/grant fit {공고명 또는 목록 번호}
```
- 맨 위 판정과 자격 게이트 표를 읽습니다. 자격에서 막히면 기술 요건은 보지 않습니다
- [트랙 1] 대부분 "부적합·부분"이 나옵니다. 증빙이 쌓여야 맞는 공고가 보입니다
확인할 것: 판정 근거가 내 KB 파일(프로필·보유역량)을 가리킵니다

■ STEP 3. 기획하기 — 주제 고르기
- (시간이 있으면 먼저) /market {주제}  → 15-market, 맨 위 한 줄 결론과 반대 신호를 봅니다
```
/scenario {주제}
```
- 점수보다 한 줄 근거를 읽고, 근거가 약한 점수에 표시합니다. 하나는 내가 고릅니다
확인할 것: 고른 시나리오의 "첫 4주에 할 일"이 다음 주에 바로 할 수 있는 일입니다

■ STEP 4. 만들기 — 기획서
```
/plan 시나리오 {번호}
```
- 맨 위 "먼저 볼 것" 표에서 "없음"인 자원을 확인합니다. 이 상태로 갈지는 내가 정합니다
확인할 것: 40-plans 에 기획서 파일이 생겼습니다

■ STEP 5. 개선하기 — 검사하고 고치기
- 끝에 나온 형식 검사 결과에서 빠진 절이 있으면:
```
빠진 절 채워 줘
```
- (시간이 있으면) 세 관점 검토 후 하나만 반영:
```
/review 40-plans/{파일 이름}
```
확인할 것: 검사 결과에 빠진 절이 없거나, 남긴 이유가 적혀 있습니다

■ 강사 결과와 비교하려면
examples\모범결과\lab3\ — 강사 주제로 사전 실행한 문헌표, 공고 목록, 적합도 판정(부적합 예시), 시나리오, 기획서

막히면 "도와줘", 요청문을 다시 보려면 "STEP 2 다시", 끝나면 "완료".
````

## 막히면

| 증상 | 이렇게 다시 말합니다 |
|---|---|
| /lit 결과가 너무 적음 | "검색어를 영어 동의어로 넓혀 다시 찾아 줘" |
| 문헌표에 없는 논문 같음 | "cite_check.py 로 방금 문헌표 인용 확인해 줘" |
| /grant search 0건 | "검색어를 한 단어로 줄이거나 AI·AX·자율로 넓혀 다시 찾아 줘" |
| 공고 사이트 접속 실패 | 인터넷·프록시 문제. "examples\모범결과\lab3\50-grants 의 공고 목록으로 이어서 해 줘" |
| fit 판정이 전부 "없음" | KB가 비어 있는 것입니다. /lab2 를 먼저 하거나 결과를 "증빙이 쌓이면 바뀌는 칸"으로 읽습니다 |
| /scenario 후보가 하나뿐 | "후보를 세 개 이상으로 넓혀서 다시 비교해 줘" |
| /plan 이 시나리오를 못 찾음 | "20-scenarios 의 {파일} 에서 시나리오 {번호}로 기획서 써 줘" |
| 시간이 모자람 | STEP 4·5는 "examples\모범결과\lab3\40-plans 의 기획서를 보여 줘"로 대신 읽습니다 |

## 정리 (완료·/wrap·끝)

먼저 회고 한 줄을 묻고("가장 쓸모 있었던 것 한 줄 적어 주세요") 답을 받은 뒤 아래를 합니다. 완료 시각은 `YYYY-MM-DD HH:MM`, `.lab-progress.json` 의 `last_activity` 에도 같은 시각을 적습니다.

1. 확인: `10-literature/`, `50-grants/`(목록과 fit 결과), `20-scenarios/`, `40-plans/`.
2. `90-log/실습/lab3.md`:
   ```markdown
   # 실습 3 — 주제 하나로 끝까지
   - 완료: {날짜 시각} · 주제: {주제}
   ## 5단계
   - 1 질문하기: /lit → {문헌 수}건, 빈틈 {한 줄}
   - 2 검토하기: /grant search {N}건 → /grant fit {공고명}: {판정} (보유 {N}·부분 {N}·없음 {N})
   - 3 기획하기: /scenario → 고른 시나리오 {번호·이름}, 고른 이유 {한 줄}
   - 4 만들기: /plan → {파일}
   - 5 개선하기: 형식 검사 {통과/보완한 절}
   ## 회고
   {참가자 한 줄}
   ```
3. `.lab-progress.json` 의 `done` 에 `lab3` 추가.
4. 다음 안내: "`/lab4` 로 오늘 만든 공간을 내일도 쓰게 만듭니다."
