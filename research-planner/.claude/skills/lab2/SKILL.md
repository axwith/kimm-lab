# /lab2 — 실습 2 · 내 연구 워크스페이스 만들기

공통 규칙: `.claude/skills/_공통규칙.md` (흐름·막힐 때·정리 방식)

## 전체 보기 (맨 먼저 그대로 출력, 아무것도 실행하지 않음)

```
실습 2 — 내 연구 워크스페이스 만들기

목표: 이 폴더가 "나"를 알고 시작하게 만듭니다. 내가 누구이고 어떻게 일하는지,
내 자료에서 어떤 문서 스타일과 실적이 보이는지를 파일로 남깁니다.

STEP 1. 질문하기 — /onboarding 인터뷰 8문항에 답합니다
STEP 2. 기획하기 — 넣을 자료를 고릅니다(오늘은 최근 공개 자료 10개 이내)
STEP 3. 만들기 — /kb ingest 가 자료마다 요약 카드·스타일·실적을 정리합니다
STEP 4. 검토하기 — "이렇게 이해했어요"를 읽고 틀린 곳을 고칩니다
STEP 5. 개선하기 — 새 세션이 나를 알고 시작하는지 보고, 내가 쓰던 방식과 비교합니다

끝나면 남는 것: 70-kb/profile/연구프로필.md, 70-kb/style/작업스타일.md·용어집.md,
70-kb/sources/ 요약 카드, 70-kb/assets/보유역량.md, CLAUDE.md 의 "나에 대해"
```

## 선택 (AskUserQuestion)

- header `방식`, question "실습 2를 어떤 방식으로 할까요?"
  - "강사 따라 하기" — 처음 쓰는 분. 강사의 공개 자료와 인터뷰 답으로 강사 화면과 같은 결과를 만듭니다
  - "내 자료로" — 이미 써 본 분. 내 공개 자료로 만들고, 내가 쓰던 방식과 비교합니다

## 자동 셋업 (선택 뒤 스킬이 바로 실행)

- 트랙 1: `examples/강사-따라하기/inbox/` 의 파일을 `00-inbox/` 로 복사합니다(PowerShell `Copy-Item examples/강사-따라하기/inbox/* 00-inbox/`, bash `cp examples/강사-따라하기/inbox/* 00-inbox/`).
- 트랙 2: `00-inbox/` 의 파일 수를 셉니다(README.md 제외). 10개를 넘으면 "오늘은 최근 것 10개만 남기고 나머지는 빼 두세요"라고 안내합니다.
- `90-log/실습/` 폴더가 없으면 만듭니다. `.lab-progress.json` 에 `{"lab2": {"track": 1 또는 2, "started": 날짜}}` 를 씁니다.
- 한 줄 보고: "실습 2 준비 완료. 트랙 {1/2}. 00-inbox 자료 {N}개."

## 브리핑 + 진행 안내 (한 메시지로 출력, 트랙에 맞는 줄만)

````
■ 이번 실습에서 쓰는 것
| 이름 | 한 줄 정의 |
|---|---|
| /onboarding | 인터뷰와 내 자료로 프로필·작업 스타일·CLAUDE.md 를 채우는 명령 |
| 00-inbox | 흡수할 자료를 넣는 폴더. 흡수가 끝나면 원본은 00-inbox\_done 으로 |
| /kb ingest | 자료마다 요약 카드를 만들고, 실적·스타일·용어를 70-kb 에 등재 |
| 70-kb | 내 지식베이스. /grant fit·/scenario·/plan 이 모두 여기를 먼저 읽음 |

흐름: 인터뷰 → 자료 넣기 → 흡수 → "이렇게 이해했어요" 확인 → 파일 반영
핵심: 실적은 증빙(자료)이 있을 때만 "보유"로 적힙니다. 이 구분이 실습 3의 공고 적합도 판정에 그대로 쓰입니다.

■ STEP 1. 질문하기 — 나를 알려 주기
이렇게 보냅니다:
```
/onboarding
```
- 선택 질문은 선택지 창에서 고르고, 나머지는 한두 줄로 답합니다
- [트랙 1] examples\강사-따라하기\인터뷰답.md 의 답이 자동으로 쓰입니다. 화면의 답만 확인합니다
- 과제명·미공개 내용은 답하지 않습니다
확인할 것: 8번 관심 주제가 실습 3의 주제가 됩니다

■ STEP 2. 기획하기 — 넣을 자료 고르기
- [트랙 1] 강사 자료 5개가 이미 00-inbox 에 있습니다. 탐색기로 열어 무엇인지 봅니다
- [트랙 2] 탐색기에서 00-inbox 에 최근 공개 자료 10개 이내를 복사합니다
  넣을 것: 내가 쓴 논문, 학회 발표, 공개 보고서, 공개 과제 요약 (HWP는 PDF로)
  넣지 않는 것: 기관 내부 문서, 미공개 데이터·시험 결과, 장비 정보, 개인정보
- 다 넣었으면 선택지 창에서 "다 넣었어요"를 고릅니다
확인할 것: 넣은 파일이 모두 이미 공개한 자료입니다. 넣은 파일은 처리를 위해 Anthropic 서버로 갑니다

■ STEP 3. 만들기 — 흡수와 반영
- 흡수는 자동으로 돕니다. 파일 쓰기 승인 창을 읽고 허용합니다
- 끝나면 70-kb\sources 의 카드 하나를 열어 요지·방법·수치·원본 위치를 봅니다
- 70-kb\assets\보유역량.md 에서 "보유"와 "부분"을 봅니다
확인할 것: "보유"는 증빙이 있는 것뿐입니다

■ STEP 4. 검토하기 — "이렇게 이해했어요" 대조
- 하는 일, 문서 스타일, 용어, 증빙 있는 실적을 내 실제 문서와 한 줄씩 비교합니다
- 틀린 곳이 있으면 "고칠 곳이 있어요"를 고르고 이렇게 보냅니다:
```
○○는 틀렸어, △△야. 고쳐서 다시 보여 줘
```
확인할 것: 스타일 표 항목 하나 이상을 내 문서와 직접 대조했습니다

■ STEP 5. 개선하기 — 반영 확인과 차용
- CLAUDE.md 맨 아래 "## 나에 대해"를 엽니다
- 새 세션을 열고 이렇게 보냅니다:
```
나에 대해 아는 것을 말해 줘
```
- [트랙 2] 내가 쓰던 방식과 비교합니다:
```
내가 원래 쓰던 방식은 ○○야. 이 워크스페이스와 비교해서 여기만 있는 것, 나만 있는 것, 가져다 쓸 것을 표로 정리해 줘
```
확인할 것: 새 세션의 답에 오늘 정한 내용이 나오고, (트랙 2) 가져다 쓸 것 하나를 메모했습니다

■ 강사 결과와 비교하려면
examples\모범결과\lab2\ — 강사 자료 5개로 사전 실행한 70-kb 와 CLAUDE.md "나에 대해"
내 결과가 다 만들어진 뒤 "모범 결과 보여 줘"라고 하면 나란히 비교해 드립니다.

막히면 "도와줘", 요청문을 다시 보려면 "STEP 3 다시", 끝나면 "완료".
````
