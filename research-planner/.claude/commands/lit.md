# /lit — 선행연구 조사와 문헌표

```text
/lit {질문}            # 조사부터 문헌표까지
/lit check {파일}      # 이미 있는 문헌표·보고서의 인용만 확인
```

## Step 1: 질문을 좁힌다

검색하기 전에 아래를 정하고 사용자에게 한 번 확인받습니다.
- 대상(재료, 구조, 장비, 현상), 방법, 보고 싶은 결과(수치, 비교, 한계)
- 기간(기본 최근 5년), 언어(기본 영어+한국어), 문헌 종류(학술지, 학회, 표준, 보고서)
- 프로필(`70-kb/profile/연구프로필.md`)의 `[비공개]` 항목은 검색어에 넣지 않습니다.

## Step 2: 찾는다

1. insane-research 가 켜져 있으면 공개 주제로 조사를 맡깁니다. 결과 보고서는 `10-literature/sources/` 에 저장합니다.
2. 막힌 페이지(403, 캡차)는 insane-search 로 읽습니다.
3. 플러그인이 없으면 웹 검색으로 같은 일을 합니다.

## Step 3: 문헌표

`10-literature/{YYYY-MM-DD}-{주제}-lit-review.md` 에 표를 만듭니다.

| 열 | 내용 |
|----|------|
| 문헌 | 저자, 연도, 제목, DOI 또는 URL |
| 대상·방법 | 무엇을 어떻게 했나 |
| 핵심 수치 | 원문에 있는 수치만, 단위 포함 |
| 한계 | 저자가 밝힌 한계 또는 조건 |
| 우리 연구와의 관계 | 같다 / 보완 / 반대 / 빈틈 |
| 등급 | `frameworks/craap-test.md` 기준 |

표 아래에 `## 빈틈` 절을 두고, 아무도 하지 않았거나 조건이 다른 부분을 적습니다. 이 절이 `/scenario` 의 입력이 됩니다.

## Step 4: 인용 실재 확인 (생략 금지)

```bash
python3 60-scripts/cite_check.py file 10-literature/{파일}.md
```

- `NOT_FOUND`, `RETRACTED` 행은 표에서 빼고 `## 미확인` 절로 옮깁니다.
- `FETCH_FAIL` 은 "확인 못 함"으로 표시하고 지우지 않습니다.
- DOI 가 없는 문헌(보고서, 표준)은 URL 을 직접 열어 제목이 맞는지 확인합니다.

## 품질 게이트

- 핵심 주장마다 독립 출처 2개 이상이거나, 1개뿐이면 그렇다고 적었는가
- 원문에 없는 수치를 쓰지 않았는가
- 모든 인용이 Step 4 를 거쳤는가
