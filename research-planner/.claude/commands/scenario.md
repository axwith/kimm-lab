# /scenario — 연구 시나리오 도출과 평가

```text
/scenario                 # 프로필 전체에서 시나리오 도출
/scenario {주제}          # 특정 주제로 좁혀 도출
/scenario compare {파일}  # 이미 있는 시나리오 다시 평가
```

## Step 0: 읽기

`70-kb/profile/연구프로필.md`, `70-kb/assets/보유역량.md`, `10-literature/` 의 최근 문헌표(특히 `## 빈틈`), `15-market/` 의 시장 조사, `50-grants/` 의 공고 검색 결과를 읽습니다. 프로필이 없으면 `/start` 를 먼저 권하고 멈춥니다.

## Step 1: 넓히기

현재 연구에서 아래 여섯 방향으로 후보를 10개 안팎 뽑습니다. 이 단계는 내부 메모이고 저장하지 않습니다.

1. 같은 방법, 다른 대상
2. 같은 대상, 다른 방법
3. 조건·규모를 넓히기(온도, 하중, 크기, 기간)
4. 이미 가진 데이터 다시 쓰기
5. 다른 분야 방법 들여오기(예: 머신러닝, 디지털 트윈)
6. 현장 문제나 공고에서 거꾸로 찾기

## Step 2: 근거 붙이기

후보마다 "이미 누가 했는가"를 확인합니다. insane-research 또는 웹 검색으로 공개 주제만 찾습니다. 근거를 찾지 못하면 "차별점 미확인"으로 표시합니다. 이미 충분히 연구된 후보는 이유와 함께 탈락시킵니다.

## Step 3: 시나리오 3~5개 작성

`20-scenarios/{YYYY-MM-DD}-{주제}.md` 에 시나리오마다 아래 절을 씁니다.

```
## 시나리오 N: {제목}
### 연구 질문
### 가설
### 방법과 필요한 실험·분석
### 필요한 자원          (표: 자원 | 상태 보유/부분/조달 가능/없음 | 증빙)
### 기대 결과물          (논문 / 특허 / 데이터 / 과제 — 수치는 쓰지 않는다)
### 차별점과 근거        (출처 링크, 없으면 "미확인")
### 위험과 대안
### 첫 4주에 할 일
```

자원 상태는 `frameworks/rfp-fit-matrix.md` 의 정의를 따릅니다. `70-kb/assets/` 에 증빙이 없으면 "보유"라고 쓰지 않습니다.

## Step 4: 평가

`frameworks/scenario-rubric.md` 로 여섯 기준을 1~5점으로 매기고, 점수마다 근거 한 줄을 붙입니다. 문서 맨 위에 비교표를 둡니다. 점수 합으로 순위를 정하지 말고, 기준별 강점과 약점을 보여 줍니다. 무엇을 할지는 연구자가 정합니다.

## Step 5: 확인과 다음 단계

```bash
python3 60-scripts/check_planner.py 20-scenarios/{파일}.md
```

연구자가 하나를 고르면 `/paper {시나리오}` 또는 `/plan {시나리오}` 를 권합니다. 과제로 내고 싶으면 `/grant search {키워드}` 를 권합니다.
