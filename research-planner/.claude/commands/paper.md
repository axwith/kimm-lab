# /paper — 논문 기획서

```text
/paper {시나리오 파일 또는 주제}
```

결과를 쓰는 명령이 아니라, 쓰기 전에 무엇이 필요한지 정하는 명령입니다.

## Step 0: 읽기

프로필, 보유역량, 해당 시나리오, 관련 문헌표를 읽습니다. 시나리오가 없으면 주제를 받아 `## 연구 질문` 과 `## 가설` 부터 함께 정합니다.

## Step 1: 기획서 작성

`30-papers/{주제}/{YYYY-MM-DD}-plan.md` 에 `frameworks/paper-planning.md` 의 절을 모두 씁니다.

- 가제 3개와 핵심 기여 세 줄
- 연구 질문과 가설
- IMRaD 골격(`frameworks/imrad-structure.md`): 절마다 들어갈 내용과 필요한 데이터
- 그림·표 계획: 그림마다 "어떤 데이터로 어떤 주장을 보이나"
- 필요한 실험·분석 목록: 보유 데이터로 되는 것 / 새로 해야 하는 것
- 선행연구 위치: `10-literature/` 에서 cite_check 를 통과한 문헌만
- 목표 저널·학회 후보 2~3곳: 범위(aims & scope) 링크를 붙이고, 영향력 지표는 확인한 값만 씁니다
- 일정: 투고 목표일에서 거꾸로 계산
- 저자와 기여: 초안만, 결정은 연구자

## Step 2: 분석 도구 확인

분석 코드가 필요하면 docs-guide 로 쓰려는 라이브러리의 공식 문서를 확인하고, 함수와 버전을 기획서의 `## 분석 방법` 에 적습니다.

## Step 3: 확인

```bash
python3 60-scripts/check_planner.py 30-papers/{주제}/{파일}.md
python3 60-scripts/cite_check.py file 30-papers/{주제}/{파일}.md
```

## 금지

- 아직 하지 않은 실험의 수치, p 값, 성능 향상 퍼센트를 쓰지 않습니다. 기대 결과는 "가설"로 씁니다.
- 저널 수락률, 심사 기간을 출처 없이 쓰지 않습니다.
