# Research Planner — 연구 기획 워크스페이스

> 지금 하고 있는 연구에서 출발해 다음 연구 시나리오를 뽑고, 논문과 연구를 기획하는 공간입니다. 과제 공고 탐색과 계획서 쓰기는 그 가운데 기능 하나입니다.

## 정체성

```
이 워크스페이스는 "내 연구의 다음 단계 기획" 전용입니다.

✅ 하는 일
- 연구 프로필(분야, 방법, 장비, 데이터, 성과, 제약) 정리 — 자기 연구 대신 관심 주제로 시작해도 됩니다
- 선행연구 조사와 문헌표, 인용 실재 확인
- 시장·수요 조사(누가 필요로 하나, 정책·예산, 기업·제품)
- 연구 시나리오 도출과 비교 평가
- 논문 기획서(가제, 기여, IMRaD 골격, 그림·표 계획, 목표 저널 후보)
- 연구 기획서(목표, 단계, 자원 대조, 위험, 성과 지표, 일정)
- 과제 공고 검색, 적합도 판정, 계획서 본문
- 결과물 교차 검토

❌ 하지 않는 일
- 실험 결과·수치를 지어내기 (기대 결과는 "가설"로만 적는다)
- 확인하지 않은 문헌을 인용하기 (cite_check 통과분만 쓴다)
- 증빙 없이 "보유"라고 쓰기 (70-kb/assets 에 근거가 있어야 한다)
- 연구 방향·저자·지원 여부를 대신 결정하기 (판단은 연구자가 한다)
```

## 핵심 원칙

- **프로필이 먼저** — `70-kb/profile/연구프로필.md` 가 없으면 `/start` 부터 합니다. 모든 명령은 프로필을 먼저 읽습니다.
- **근거 아니면 미확인** — 동향·차별점·저널 정보에는 출처를 붙이고, 출처가 없으면 "미확인"으로 남깁니다.
- **가설과 결과를 섞지 않는다** — 아직 하지 않은 실험의 수치는 쓰지 않습니다.
- **보유·부분·없음은 증빙으로** — 자원 판정은 `frameworks/rfp-fit-matrix.md` 의 상태 정의를 따릅니다. "할 수 있을 것 같다"는 상태가 아닙니다.
- **계산은 스크립트로** — 인용 실재, 계획서 산술, 필수 항목 누락은 `60-scripts/` 로 확인합니다. 말로 "잘 확인해 줘"라고 맡기지 않습니다.
- **파일로 남긴다** — 결과는 정해진 폴더에 파일로 저장하고, 세션 끝에 `/wrap` 으로 기록합니다.

## 폴더 구조

```
research-planner/
├── CLAUDE.md                 # 이 파일 (규칙)
├── .claude/
│   ├── settings.json         # gptaku 플러그인 자동 등록
│   ├── commands/             # /start /lit /market /scenario /paper /plan /grant /proposal /review /wrap
│   ├── agents/               # 인용 검토, 방법 검토, 반론 찾기
│   └── hooks/                # 도구 사용 이력 기록 (logs/agent_history.jsonl)
├── frameworks/               # 판정 기준 (시나리오 평가, 논문 기획, 연구 기획, 적합도, 출처 등급)
├── 00-inbox/                 # 내 논문·보고서·메모를 넣는 곳
├── 10-literature/            # 문헌표, 출처 목록
├── 15-market/                # 시장·수요 조사
├── 20-scenarios/             # 연구 시나리오
├── 30-papers/                # 논문 기획서
├── 40-plans/                 # 연구 기획서
├── 50-grants/                # 공고 분석, 적합도, 계획서
├── 60-scripts/               # 공고 수집, 인용 확인, 계획서·기획서 검사
├── 70-kb/                    # 연구 프로필, 보유 역량 증빙, 공고 판정 기록
├── 90-log/                   # 세션 기록
├── logs/                     # 훅이 남기는 도구 사용 이력
└── examples/                 # 연습용 가상 프로필 (자기 연구 예시, 관심 주제 예시)
```

## 흐름

```text
/start → /lit {질문} → /grant search {키워드} → /market {주제} → /scenario → /paper 또는 /plan → /review → /wrap
                                                                                     └─ 과제로 낼 때: /grant fit → /proposal
```

| 명령 | 하는 일 | 저장 위치 | 쓰는 플러그인 |
|------|---------|-----------|---------------|
| `/start` | 플러그인 확인, 연구 프로필 인터뷰 | `70-kb/profile/`, `70-kb/assets/` | — |
| `/lit` | 선행연구 조사, 문헌표, 인용 실재 확인 | `10-literature/` | insane-research, insane-search |
| `/market` | 시장·수요 조사(수요자, 시장 규모, 정책·예산, 기업·제품, 반대 신호) | `15-market/` | insane-research, insane-search |
| `/scenario` | 연구 시나리오 3~5개 도출과 여섯 기준 평가(수요 포함) | `20-scenarios/` | insane-research |
| `/paper` | 논문 기획서 | `30-papers/` | docs-guide(분석 도구 확인) |
| `/plan` | 연구 기획서 | `40-plans/` | show-me-the-prd(연구용 도구가 필요할 때) |
| `/grant` | 공고 검색, 요건 분해, 적합도 판정, 과제 아이템 | `50-grants/` | insane-search |
| `/proposal` | 계획서 본문 | `50-grants/` | — |
| `/review` | 근거·방법·반론 교차 검토 | 검토 대상 옆 `review-*.md` | kkirikkiri |
| `/wrap` | 오늘 한 일과 다음 할 일 기록 | `90-log/` | — |

반복하는 일이 생기면 skillers-suda 로 내 명령(스킬)을 만들어 `.claude/skills/` 에 둡니다.

## 자료 보안

- 웹을 쓰는 플러그인(insane-research, insane-search, docs-guide)과 웹 검색에는 **공개해도 되는 주제만** 넣습니다. 기관 과제명, 미공개 데이터, 장비 정보, 협력사 이름은 검색어나 요청문에 넣지 않습니다.
- 프로필에서 외부에 알려지면 안 되는 내용은 `[비공개]` 로 표시합니다. `[비공개]` 항목은 검색어로 쓰지 않습니다.
- 기관 자료를 이 공간에 넣기 전에는 소속 기관의 AI 사용 규정을 먼저 확인합니다. Claude Code 가 읽은 파일 내용은 처리를 위해 Anthropic 서버로 전송됩니다.
- pumasi(OpenAI Codex), insane-review(ChatGPT)는 자료를 다른 회사로도 보내므로 기본으로 켜지 않습니다.

## 산출물 규칙

- 파일 이름: `{YYYY-MM-DD}-{주제}.md`. 같은 주제를 다시 하면 새 날짜로 만들고 이전 파일은 지우지 않습니다.
- 문서 끝에 `## 미확인` 절을 둡니다. 근거를 찾지 못한 주장, 사람이 정해야 할 것을 모읍니다.
- 저장한 뒤 `python3 60-scripts/check_planner.py {파일}` 로 필수 항목을 확인합니다. 계획서는 `check-submission.py`, 인용이 있으면 `cite_check.py file {파일}` 도 돌립니다.
- 명령 파일의 `python3` 는 macOS·Linux 기준입니다. Windows 에서는 `python`(또는 `py`)으로 바꿔 실행하고, 가상환경이 있으면 그 안의 `python.exe` 를 씁니다. 스크립트는 표준 라이브러리만 쓰고 출력은 UTF-8 로 고정돼 있습니다.
- 판정 기준의 정본은 `frameworks/` 입니다. 명령 파일과 기준이 어긋나면 기준을 따르고 어긋남을 보고합니다.

## 교육 배포본 규칙 (한국기계연구원 교육, 2026-10-15)

- 처음 열었는데 `70-kb/profile/연구프로필.md` 가 없으면 `/lab2` 부터 권한다(`/lab2` 가 그 안에서 `/onboarding` 을 진행한다. `/onboarding` 을 따로 먼저 하라고 하지 않는다). 실습은 `/lab2` `/lab2b` `/lab3` `/lab4` 스킬로 안내한다. 실습 1은 스킬 없이 `first` 빈 폴더에서 한다(`/lab1` 은 없다).
- 새 세션의 첫 응답 전에(질문·잡담·명령 등 어떤 요청이든): `90-log/_queue/` 에 처리 안 된 파일(`처리함.txt` 에 이름이 없는 .jsonl)이 있으면 묻지 않고 `/wrap` 의 "대기열 처리"(.claude/commands/wrap.md 끝 절)를 먼저 실행하고, 처리했다고 한 줄로 알린다. 폴더가 없거나 비었으면 처리할 것이 없다(없는 폴더를 직접 열어 오류를 내지 말고 `90-log/` 부터 본다). 그다음 90-log의 가장 최근 기록을 읽고 확정한 것·미확인·다음 행동을 짧게 요약한다. 기록이 없으면 없다고 알리며 추측하지 않는다. 단, `/lab2`·`/lab2b`·`/lab3`·`/lab4` 로 시작한 세션은 스킬의 "전체 보기"를 첫 응답 맨 앞에 그대로 출력하고, 대기열·기록 확인 결과는 그 아래 한 줄로만 쓴다.
- 이 앱의 Claude Code에는 Glob·Grep 도구가 없다. 파일 목록과 검색은 Read 와 Bash 의 읽기 전용 명령(ls, find, grep / Windows PowerShell은 Get-ChildItem, Select-String)으로 한다.
- 파일·폴더가 있는지, 무엇이 들었는지는 Read 도구나 읽기 전용 명령(`ls`·`find`, PowerShell `Get-ChildItem`)으로 확인한다. 지우기·옮기기 명령은 쓰지 않는다.
- `/lit` `/market` `/grant search` 에 주제가 없으면 프로필의 관심 주제를 쓰고, 무엇을 썼는지 첫 줄에 밝힌다.
- 문서를 쓸 때는 `70-kb/style/` 의 작업 스타일과 용어집을 따른다. 스타일 파일과 이 규칙이 어긋나면 이 규칙이 우선이다.
- 더한 명령: `/onboarding`(나를 알려 주기·자료 흡수·반영), `/kb`(지식베이스 흡수·조회·점검), `/weekly`(주간 공고 스캔). 강의 뒤 KB 키우기는 `KB-구축가이드.md`.
