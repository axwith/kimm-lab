# 주간 논문 수 알리미 -- 데이터 모델

> 앞선 가정(A1~A8)은 [01_PRD.md](./01_PRD.md) 맨 위 표를 참고하세요.
> 개발자가 아니어도 이해할 수 있는 개념적 구조입니다.

---

## 전체 구조

```
[주제 Topic] --1:N--> [주간집계 WeeklyCount] <--N:1-- [출처 Source]
     |
     └--1:N--> [키워드 Keyword]

[실행기록 Run] --1:N--> [주간집계]
```

⚠️ 가정 A7: 저장소는 SQLite 파일 하나. 아니라면 알려주세요.

---

## 엔티티 상세

### 주제 (Topic)
추적하는 관심 주제 하나.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 식별자 | 1 | O |
| name | 보기용 이름 | 예지보전 | O |
| active | 추적 여부 | true | O |
| created_at | 등록일 | 2026-10-14 | O |

### 키워드 (Keyword)
주제를 검색할 때 쓰는 단어. 공개해도 되는 단어만 넣는다.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 식별자 | 10 | O |
| topic_id | 소속 주제 | 1 | O |
| term | 검색어 | predictive maintenance | O |
| is_exclude | 제외어 여부 | false | O |

### 출처 (Source)
건수를 가져오는 곳.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 식별자 | 1 | O |
| name | 출처 이름 | openalex | O |
| note | 한도·주의 | 호출 한도 미확인 | X |

### 주간집계 (WeeklyCount)
주제 × 출처 × 주차 별 건수. 이 표가 이력의 핵심이다.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 식별자 | 100 | O |
| topic_id | 주제 | 1 | O |
| source_id | 출처 | 1 | O |
| week_start | 해당 주의 월요일 | 2026-10-05 | O |
| count | 건수. 조회 실패면 비워 둔다 | 42 | X |
| status | ok / failed | ok | O |
| run_id | 만든 실행 | 7 | O |

같은 (주제, 출처, week_start)는 한 줄만 허용 → 재실행해도 중복되지 않는다.

### 실행기록 (Run)

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 식별자 | 7 | O |
| started_at | 실행 시각 | 2026-10-12 08:00 | O |
| note | 오류 요약 | openalex 429 | X |

### 관계
- 주제 1개에 키워드 여러 개
- 주제 1개에 주차별·출처별 집계 여러 개
- 실행 1회가 집계 여러 줄을 만든다

---

## 왜 이 구조인가

- 확장성: 출처를 늘려도 `Source` 행만 추가하면 된다. 여러 사용자는 `User`를 위에 얹으면 된다(Phase 3).
- 단순성: 논문 개별 정보는 저장하지 않는다(건수만). Phase 2에서 대표 논문 링크가 필요해지면 `Paper(doi, title, url)`를 추가한다.
- 실패를 0과 구분하기 위해 `status`를 둔다. 0편과 조회 실패를 섞으면 증감이 거짓이 된다.
