---

## 기술 스택

| 영역 | 선택 | 이유 |
|------|------|------|
| 언어 | Python 3 (표준 라이브러리 위주) | 이 워크스페이스의 `60-scripts/`가 표준 라이브러리만 쓰는 방식이라 맞춘다(⚠️ 가정 A7) |
| 저장 | SQLite 파일 1개 | 서버 불필요, 본인용에 충분 |
| 출처 | OpenAlex(Phase 1), arXiv(Phase 2) | 무료 공개 서지 API라는 점은 알려진 사실이나 **호출 한도·날짜 필터는 직접 확인 전(A4)** |
| 설정 | `topics.yaml` 또는 JSON | 사람이 직접 편집. YAML 파서가 표준 라이브러리에 없으니 JSON도 허용 |
| 실행 | cron / launchd 예약 | 서버 없이 본인 컴퓨터에서(⚠️ 가정 A6) |
| 발송 | Phase 2에서 결정 | 메일 서비스 키가 필요하면 tikeytaka 볼트로 관리 |

## 프로젝트 구조

```
paper-count-weekly/
├── topics.yaml        # 주제·키워드·제외어
├── src/
│   ├── fetch.py       # 출처별 건수 조회
│   ├── store.py       # SQLite 읽기/쓰기
│   └── report.py      # 마크다운 리포트
├── data/counts.sqlite # 이력 (git 제외)
├── reports/           # 주차별 리포트
└── tests/
```

## 절대 하지 마 (DO NOT)

- [ ] API 키·메일 비밀번호를 코드나 설정 파일에 직접 쓰지 마 (.env 또는 키 볼트 사용)

- [ ] 기관 과제명·미공개 데이터·장비·협력사 이름을 검색어에 넣지 마 (공개 키워드만)
- [ ] 목업/하드코딩 데이터로 완성이라고 하지 마
- [ ] 기존 DB 스키마를 임의로 변경하지 마 (변경 시 마이그레이션 계획 먼저)
- [ ] 출처 API 호출 한도를 확인하기 전에 반복 호출 루프를 돌리지 마
- [ ] 테스트 없이 예약 실행에 등록하지 마

## 테스트 방법

```bash
# 로컬 실행
python3 src/report.py --topics topics.yaml

# 단위 테스트
python3 -m unittest discover tests

# 같은 주 재실행해도 행 수가 늘지 않는지 확인
python3 src/report.py --topics topics.yaml && sqlite3 data/counts.sqlite "select count(*) from weekly_count"
```

## 배포 방법

Phase 1은 배포가 아니라 본인 컴퓨터의 예약 실행이다(macOS는 launchd, 그 외 cron). 서버 이전은 Phase 2 이후 필요할 때 결정.
