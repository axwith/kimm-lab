## 1. 제품 개요

### 한 줄 요약
내가 정한 관심 주제별로, 지난주에 새로 나온 논문이 몇 편인지 매주 한 번 받아 보는 도구.

### 해결하는 문제
관심 분야의 논문이 늘고 있는지 줄고 있는지 알려면 검색 사이트를 매번 직접 열어 날짜 필터를 걸어야 한다. 그래서 주제 열기가 식고 동향을 놓친다. (⚠️ 가정: 실제 불편 장면은 인터뷰하지 않았다 — 아니라면 알려주세요)

### 핵심 가치
- 목록이 아니라 **숫자와 추세**를 준다(읽을 부담 없음). 필요하면 상위 몇 편의 제목 링크를 덧붙인다.
- 연구 기획(`/lit`, `/scenario`)에서 "이 주제가 뜨는 중인가"를 판단할 근거가 쌓인다.

---

## 2. 사용자

### 주요 사용자
- **누구**: 연구 기획을 하는 연구자 본인
- **상황**: 월요일 아침 메일함, 또는 `90-log`에 쌓인 주간 파일
- **목표**: 주제별 신규 논문 수와 증감을 30초 안에 훑기

### 사용자 시나리오
1. 연구자가 `topics.yaml`에 주제 3~10개와 키워드를 적는다.
2. 매주 월요일 예약 실행이 돌아 주제별 지난 7일 논문 수를 센다.
3. 수신함에 표 한 장(주제 / 이번 주 / 지난 주 / 증감 / 4주 평균)이 도착한다.

## 4. 사용자 흐름 (User Flow)

### 핵심 흐름
```
topics.yaml 작성 -> 예약 실행(주 1회) -> 출처 API 조회 -> 건수 저장 -> 리포트 생성 -> 확인
```

### 상세 흐름
1. **설정**: 주제와 키워드를 적는다. 제외어로 노이즈(동음이의어)를 줄인다.
2. **수집**: 주제별로 날짜 범위 `지난 월~일`로 조회한다. 실패한 출처는 리포트에 "조회 실패"로 표시하고 0으로 쓰지 않는다.
3. **리포트**: 건수·증감·4주 평균. 첫 주는 비교 대상이 없으므로 "기준선 수집 중"으로 표시한다.

## 5. 성공 기준

- [ ] 주제 3개로 실제 API를 호출해 지난 7일 건수가 나온다(목업 아님)
- [ ] 같은 주를 두 번 실행해도 이력이 중복 저장되지 않는다
- [ ] 사람이 검색 사이트에서 같은 조건으로 센 값과 주제 1개 이상에서 대조해 큰 차이가 없음을 확인했다(허용 오차는 미정)
- [ ] 한 출처가 실패해도 나머지 리포트가 나온다

## 6. 안 만드는 것 (Out of Scope)

> Phase 1에서 만들지 않습니다. AI에게 코드를 시킬 때 함께 공유하세요.

- 웹/앱 화면 -- 이유: 가정 A2, 숫자 몇 개에 화면은 과하다
- 논문 본문 요약·번역 -- 이유: 건수 알림이 목적이고 요약은 비용·환각 위험이 있다
- 로그인·다중 사용자 -- 이유: 본인용이다
- 논문 품질 평가·인용 수 순위 -- 이유: "많다 ≠ 좋다"를 도구가 판단하지 않는다
- 유료 데이터베이스(Scopus, WoS) 연동 -- 이유: 계약·키 필요
