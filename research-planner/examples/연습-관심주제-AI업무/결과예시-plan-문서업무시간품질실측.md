# 연구 기획서 — 연구자 문서 업무 시간·품질 교차 실측

> 고른 이유: 시나리오 1은 비교표에서 실현성 3·수요 4로 시나리오 2와 같은 수준이지만 새로움(3)과 근거 강도(4)가 함께 받쳐 주고, 시나리오 3은 실현성 2(보안 환경·기관 승인이 없음)라 혼자 시작할 수 없다.

- 작성일: 2026-10-12
- 근거 자료: `20-scenarios/2026-10-12-ai-agent-doc-work.md`(시나리오 1), `10-literature/2026-10-12-ai-agent-doc-work-lit-review.md`, `15-market/2026-10-12-ai-agent-researcher-doc-work.md`, `70-kb/profile/연구프로필.md`, `70-kb/assets/보유역량.md`

## 먼저 볼 것: 핵심 자원 상태

핵심 자원 가운데 "없음"이 둘 있다. 이 상태로 진행할지는 연구자가 정한다.

| 자원 | 상태 | 영향 |
|------|------|------|
| 본인 업무 시간 기록 | 없음 | 이 연구의 측정 자체가 이 기록이다. 1단계의 첫 산출물로 직접 만든다(만들 수 있어 막히지는 않음) |
| 재채점자(동료 1명) | 없음 | 품질 채점의 편향 통제가 약해진다. 못 구하면 1주 이상 간격을 둔 본인 재채점으로 대체하고 한계로 적는다 |
| 공동 연구자 | 없음 | 혼자 진행. 일반화 주장은 하지 않는다 |

Python 기초와 Claude Code 사용은 "부분"이다(증빙: 본인 진술, 2026-10-15 교육 이수 예정). 교육을 이수하지 않으면 2단계 이후 일정이 밀린다.

## 목표

- 최종 목표: 공공 연구기관 연구원의 문서 업무(문헌 정리, 보고서 초안, 계획서 형식 점검)에서 AI 에이전트 도구의 작업 시간·품질 효과를 재는 측정 방법을 만들고, 소규모 교차 실측으로 과제 유형별 경향을 보고한다. 이를 근거로 6개월 안에 부서 시범 연구를 제안한다.
- 1단계(2026-10-12~11-09): 측정 틀 확정 — 시간 기록 양식, 채점표, 과제 세트 8개.
- 2단계(11-10~12-21): 교차 실측 수행과 1차 집계.
- 3단계(2027-01~02): 재채점, 과제 유형별 분석, 방법·사례 보고 초안.
- 4단계(2027-03~04-12): 부서 시범 연구 제안서 작성과 제출 여부 판단.

## 단계별 내용과 방법

### 1단계: 측정 틀 확정 (4주)
- 시간 기록 양식(시작·종료·단계[생성/검토/수정]·메모)과 채점표를 만든다. 채점표는 수행 전에 고정한다.
- 공개 자료만으로 과제 8개를 정한다: 공개 논문 5~8편 정리표, 공개 공고문 요건 표, 공개 보고서 1편 요약 초안, 계획서 양식 점검. 난이도가 비슷한 짝을 지어 에이전트 사용/미사용 순서를 무작위로 배정하고 파일로 고정한다.
- 도구 이름·버전·날짜를 모든 기록에 남긴다(도구 변화가 빨라 결과 유효기간이 짧다).
- 선행 연구 3~4편(Noy & Zhang, Dell'Acqua et al., Dillon et al., Humlum & Vestergaard)의 측정 정의를 원문에서 대조해 우리 측정 정의와 맞춘다. 문헌표의 수치 불일치(40% 대 37%, 30% 대 40% 이상)를 이때 확인한다.

### 2단계: 교차 실측 (6주)
- 같은 사람이 과제를 번갈아 에이전트 사용/미사용으로 수행한다. 과제당 시간을 생성·검토·수정으로 나눠 기록한다.
- 인용이 들어간 산출물은 `60-scripts/cite_check.py` 로 실재 확인을 하고 오류 건수를 센다. 실재하는 인용이 주장을 뒷받침하는지는 원문을 열어 4단계(지지/부분 지지/불일치/열람 불가)로 판정한다(시나리오 2의 방법을 품질 측정 하위 항목으로 흡수).
- 접근 불가 원문은 삭제하지 않고 "열람 불가"로 남긴다.
- 부서 보고서와 시험 데이터는 쓰지 않는다. 기관 보고서에서 배운 "형식 유형"만 가상 과제로 옮긴다.

### 3단계: 채점과 분석 (8주)
- 눈가림 재채점: 동료 1명을 구하면 그에게, 못 구하면 수행 후 1주 이상 간격을 두고 본인이 채점표대로 다시 채점한다.
- 분석: 과제별 시간·품질 차이, 과제 유형별(형식이 정해진 업무 대 새 판단이 필요한 업무) 비교, 검토·수정 시간까지 합친 순감. Python 표준 라이브러리와 기초 통계, 표와 그림.
- 가설 1(형식 업무는 시간이 줄고 판단 업무는 순감이 작다)과 가설 2(검토 시간까지 합치면 절감폭이 줄어든다)는 예상일 뿐이며, 틀렸다는 결과도 결과로 보고한다.
- 방법·사례 보고 초안을 쓴다. 단일 사례이므로 통계적 일반화는 하지 않고 "측정 방법과 효과 크기의 대략적 범위"를 보고한다.

### 4단계: 부서 시범 제안 (6주)
- 측정 방법을 참여자 여러 명으로 확장하는 시범 연구 제안서를 쓴다. 보안 환경에서 쓸 수 있는 도구 조건과 기관 승인은 별도 확인이 필요하다(시나리오 3 영역, 이 기획서의 범위 밖).
- 제안서를 부서장에게 보일지, 어떤 형식으로 낼지는 연구자가 정한다.

## 인력과 역할

- 연구자 본인(1명): 설계, 과제 수행, 시간 기록, 채점, 분석, 보고.
- 추가 필요 인력: 재채점자 1명(품질 채점 편향 통제). 상대와 협조 가능 여부는 미정이며 연구자가 정한다.
- 시범 단계(4단계)에서는 참여 연구원 여러 명과 기관 보안·정보화 담당자 자문이 필요하다. 아직 상대가 없다.

## 연결할 과제

이번 공고 검색 후보 5건 가운데 문서 업무 에이전트 연구를 직접 받는다고 확인된 공고는 없다(`50-grants/2026-10-12-공고검색-AI에이전트.md`). 지금 시점에는 과제로 연결할 단계가 아니라 예비 결과를 만드는 단계다.

- `/grant search` 키워드: "연구행정 AI", "R&D 보고서 자동 작성", "AI 연구윤리 검증", "연구 생산성 측정", "AI 에이전트 업무 자동화 공공".
- 맞는 사업 유형 후보: 부서·기관 내부 시범 과제, 정부 R&D 행정 디지털화 과제(2027년 보고서 자동 작성 확대 계획과 연결 가능, 확인 전). 지역거점 AX 사업은 신청 자격과 과제 수용 여부가 원문 확인 전이다.
- 중소기업 대상일 가능성이 큰 공고(#1, #5)는 출연연 단독 신청이 어려울 수 있다(신청 자격 미확인).
- 과제로 낼 때는 `/grant fit` 으로 원문 요건을 먼저 대조한다.

## 미확인

- 문헌표·시나리오의 모든 수치는 웹 검색 요약 기준이며 원문 대조 전이다. 1단계에서 확인한다.
- 연구자(특히 공공 연구기관 연구원) 대상 문서 업무 시간 통제 측정은 찾지 못했다. AEARCTR-0017030의 결과는 확인하지 못했다.
- 한국어 문헌과 국내 연구자 설문은 찾지 않았다.
- Python 기초 수준과 Claude Code 사용 수준의 증빙.
- 본업과 병행할 때 주당 투입 가능 시간.
